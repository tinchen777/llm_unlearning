# 7 多层编辑（multi-layer W_down）

## 问题

- 单层编辑下 NEAR 的遗忘与 retain 保持是一条权衡曲线（见 6）：retain 越保，遗忘越弱，位移实际幅度比 0.87 → 0.45。
- 假设：把总位移**分摊到几层**，每层只需拟合更小的位移，与 retain 的冲突更小，遗忘与保持的权衡可能更好；每层的激活痕迹也可能更小（与 metric_line 的白盒指标相关）。

## 做法

- `wdown.layers=[8,9,10]` 本来就支持多层，但原实现有两个问题：
  1. **重复计数**：`r_UV` 是层输出处的差，已经包含了下面各层加进去的差；每层都加 `coeff × 整个 r_UV`，残差流把位移一路带上去，总位移约是预期的 n 倍。
  2. 各层都用**原模型**的输入训练，没有考虑下面层被编辑之后输入已经变了。
- 新增 `wdown.multi_layer`：
  - `same`：保持原行为（每层加 `coeff × 自己的 r_UV`）；
  - `increment`：最低层取整个 `r_UV`，之后每层取与上一个被编辑层的**差**（telescoping），总位移 = `coeff × 最后一层的 r_UV`，等价于只编辑最后一层，只是分摊到多层。此时 `achieved_vs_intended` 在每层都是精确的。
- 新增 `wdown.sequential`：从低到高逐层训练，训练完一层后，用已编辑的模型重新记录下一层的输入（目标不变：原输出，forget 另加位移）。这样每一层会同时修复下面编辑对它输入造成的偏移。
- 脚本：`scripts/NEAR/sweep_w_down.sh`，`LAYER=8,9 MULTI_LAYER=increment SEQUENTIAL=1`。
- 测试：`layer_increments` 单元测试 + 小模型端到端（`sequential` 与否各一次，非法 `multi_layer` 报错）。

## 结果

A / B / C 都是 `all` 模式、K=5、系数 7、`multi_layer=increment`、forget01（1B）。单层 c7/L9 是对照（`TODO/near_line/6`）。结果在 `saves/eval/NEAR/single/rw1_increment_*`。

（单层 L9 的数字取自它重评之前的结果；它的评测在重跑，当时文件还没写完。）

- **分摊到多层 + 顺序训练明显有效**：总位移与单层相同（`7·r_9`），A 就比单层好（`forget_quality` 0.41 → 0.58，`privleak` −75 → −59，`mia_loss` 0.85 → 0.75），代价只是 `model_utility` 掉了 0.013。B 再加一层：`forget_Q_A_Prob` 0.163 与 retain 模型（0.169）几乎相同，`mia_loss` 0.55 接近随机，`forget_quality` 0.77，`privleak` −26。**B 已经接近 LUNAR 的遗忘程度，`model_utility`（0.524 对 0.440）和 retain 生成质量（0.47 对 0.40）还更好，且没有拒答和乱码。**
- **`sequential` 是关键，不是可选项**：C 与 B 唯一的区别是不顺序训练，遗忘指标反而更"强"（`mia_loss` 0.468，`privleak` −2.6），但 `model_utility` 掉到 0.397、retain 答案概率 0.24。看 `w_down_summary.json`：C 的第 8、9 层 `achieved_vs_intended` 余弦分别是 −0.11 和 0.008（幅度比 2.06 和 1.81），说明独立训练时各层对上游编辑后的输入做了错误假设，累积位移的方向完全不对，是靠破坏模型"遗忘"的。顺序训练（B）各层余弦 0.98 / 0.87 / 0.85，位移方向对。
- **代价在变大**：层数越多，retain 越受损（retain 生成 ROUGE 0.636 → 0.581 → 0.474；`retain_answer_prob` 0.78 → 0.73 → 0.54）。顺序训练的上层幅度比 >1（1.05 ~ 1.16），在轻微过冲。
- **回答质量**（B）：forget 的回答是编造，但有些明显不通顺（"Basis the information, Basil It seems, the information is not confirmed."），没有被 `degenerate` 标记。这类"弱乱码"可能被黑盒观察者注意到，现有 UD 指标（拒答、乱码、近重复）抓不到，可以考虑加流畅度通道（见 metric_line）。
- 还没有的数据：这三个评测是新指标（UD）之前跑的，没有 `ud_*` 和 `anom_auc`，需要重跑第 4 步评测（命令见下）。

## 下一步

1. **压低 retain 损害**（B 的 retain ROUGE 0.47、答案概率 0.54 是目前最大的代价）：把单层时有效的两个办法用到多层——`include_answer`（单层时 retain ROUGE 0.636 → 0.760，遗忘几乎不变）和更大的 `retain_weight`：

   ```bash
   # D：B + 答案 token（retain_weight 1 和 3）
   LAYER=7,8,9 COEFF=7 MULTI_LAYER=increment SEQUENTIAL=1 INCLUDE_ANSWER=1 RETAIN_WEIGHTS="1 3" bash scripts/NEAR/sweep_w_down.sh 0
   # E：A + 答案 token（A 本身的效用损失更小）
   LAYER=8,9 COEFF=7 MULTI_LAYER=increment SEQUENTIAL=1 INCLUDE_ANSWER=1 RETAIN_WEIGHTS="1 3" bash scripts/NEAR/sweep_w_down.sh 1
   ```
2. **补跑 A、B、C 的评测以得到 `ud_*`**（只重跑第 4 步，会原地覆盖）：

   ```bash
   for v in "rw1_increment_seq_c7_l8-9:8,9" "rw1_increment_seq_c7_l7-8-9:7,8,9" "rw1_increment_c7_l7-8-9:7,8,9"; do
     SELECT_TASK_NAME=single/near_tofu_Llama-3.2-1B-Instruct_forget01 TASK_NAME=single/${v%%:*} \
       K=5 COEFF=7 MODE=all W_DOWN_LAYER="[${v##*:}]" bash scripts/NEAR/single_run.sh 0 "4"
   done
   ```
3. 之后可以考虑：四层（6–9）、再细调系数（过冲时降到 6）、forget05 上验证。
