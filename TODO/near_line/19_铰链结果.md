# 19 铰链（真实答案概率）的结果（1B，forget01）

## 问题
KL 项约束邻居答案前缀，不降低真实答案的概率（near_line/17）。加一个直接针对真实 forget 答案的铰链项（`wdown.kl.forget_prob_weight` μ，目标 τ=0.17=retain 模型的 Prob，只惩罚高于 τ 的部分）能否在不增加白盒痕迹的前提下把 Prob 压到 retain 水平？

## 做法
`kl_layers/5_forget_prob.sh`：层 11-12-13，c {1, 1.5}，μ {1, 3}，KL=1，τ=0.17，`increment` + `sequential` + 答案 token，fast 评测。

训练日志（μ1）：训练中真实答案概率 0.861 → 0.080（c1）、0.816 → 0.102（c1.5），铰链惩罚 1.6 → 0（已低于目标），KL 4.9 → 0.56，forget 相对 MSE 0.029 → 0.053。forget 回答仍是通顺的另一个说法（"The full name of the author … is Hisham Al-Awadhi."），`degenerate`=0，首词是邻居式的名字。

## 结论
1. **铰链把"痕迹–遗忘"前沿大幅推动了**：在同样的白盒痕迹（c1，l11-13：`wb_unsup` 0.57）下，Prob 从 0.556 降到 0.08，utility 不变（0.569），retain 生成 0.689（KL 对照 0.754，少 0.065），无乱码，`ud_bb` 0。这是第一个同时打破"Prob 与 `wb_unsup` 同向"的点：之前遗忘到 retain 水平只能靠 c7（`wb_unsup` 0.996）。
2. **但它过冲了**：目标 0.17，实际 0.08；mia 0.22（retain 0.483）= 过度遗忘（正是我们批评 LUNAR 的地方）；extraction 0.118（retain 0.062，反而更高）。所以现在的点是"遗忘过头"，要调到 retain 水平（Prob ≈ 0.17、mia ≈ 0.48）才算数。过冲的原因是铰链只在高于目标时有梯度，学习率下动量把它推过目标。
3. μ=3 比 μ=1 更差（retain 生成 0.606 对 0.689，`wb_unsup` 0.617 对 0.569）：μ=1 就够了。c1.5 的白盒仍 0.93，说明要保持低痕迹必须留在 c1（甚至更小）。
4. **需要警惕的**：铰链直接降低训练用 forget 问答的真实答案概率（和 NPO、GradAscent 一样用了 forget 答案），评测的 `forget_Q_A_Prob` 就是这批问答，**可能高估泛化**；fast 配置没有释义 / 扰动问题上的 Prob（`forget_Q_A_PARA_Prob`、`PERT`），需要对入选的点补跑 full 评测。

## 目标值来自 retain 模型吗（用户提出的问题）
**是的**：上面的运行用的 τ=0.17 就是 retain 模型的 `forget_Q_A_Prob`，这违反了"只知道原模型和遗忘数据"的设定（与 baseline 按 retain 指标选 epoch 是同一类问题）。修正：τ 不再取自 retain 模型，而取**原模型在未见数据上的答案概率**（TOFU 的 holdout 作者，`forget_prob_target: unseen`）。数据支持这个替代：full 模型在 holdout 上的答案概率 1B 0.161 / 3B 0.159 / 8B 0.130，对应 retain 模型的 forget Prob 0.169 / 0.178 / 0.139（差 0.01–0.02）。邻居答案的概率更低（full 模型 0.082 / 0.082 / 0.069，GPT 生成的答案更短更难预测），不适合直接作 τ。**上面表里的结果（τ=0.17）应标注为"用了 retain 模型的值"，不能作为最终方法的结果**；新运行用 `unseen`。另外铰链新增 `forget_prob_mode: match`（双向：向 τ 靠拢，而不是只惩罚高于 τ），用来解决过冲；任何"把 τ 调到 0.25 / 0.35 补偿过冲"的做法都是用 retain 水平的指标在调参，也算用了 retain 参照，只作对照。
