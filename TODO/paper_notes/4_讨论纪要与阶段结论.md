## 1. 目标与论点：不比谁遗忘得更狠，比谁遗忘得"像没学过"且不露痕迹
- 起点：LUNAR / DPO / NPO 的拒答本身就是被遗忘过的痕迹，攻击者可据此发现被遗忘的实体（*Extracting Forgotten Prompts from Targeted Unlearned Models*，TAS 攻击）。论文自己的防御方向是"让被遗忘输入与普通输入行为不可区分"，这就是 NEAR 的定位。
- 论点（草稿）：*"我们不追求在原始遗忘指标上超过 LUNAR，而是在**遗忘到与 retain 模型相当的程度**时，比较保持效用和可检测度；此时 NEAR 保持更高的效用（0.57 对 0.40）与更好的 retain 生成质量，并且在黑盒下不可检测（`ud_bb` 0.05，对 LUNAR 的 0.52）。"*
- 我们**不**主张：NEAR 在白盒下更隐蔽（见 §5）。

## 2. 为什么"LUNAR 的 Prob 更低"不代表它遗忘得更好（用户的洞察，已核实）
- `forget_Q_A_Prob` 是 teacher forcing 下**标准答案 token 的平均概率**（每个样本 exp(−平均交叉熵)，再对样本平均），不是生成句子的相似度；衡量的是概率质量去了哪里。
- LUNAR 把概率质量压到拒答句上，标准答案被压得比从没学过的 retain 模型（0.169）还低（c1.5：0.115，c2：0.024），所以"看起来遗忘得很干净"；对应 forget 回答 55–70% 是拒答（TAS）、ROUGE 0.07–0.10、mia 0.10–0.43（retain 0.48，过度遗忘）。
- NEAR 不拒答，回答是通顺的另一个说法，ROUGE 0.26–0.29（retain 0.42），幻觉率 0.50–0.575（retain 0.325）：口气像、信息点是错的。
- **结论**：评价口径是"与 retain 相近"（Prob ≈ 0.17、mia ≈ 0.48、extraction ≈ 0.06），不是"越低越好"。过度遗忘本身就是可被发现的痕迹。Pareto 匹配表据此规定：Prob ≤ 0.25 **且** |mia − retain 的 mia| ≤ 0.25 才算"遗忘到 retain 水平"，防止把 NPO / GradAscent 后期崩溃的点（mia ≈ 0）当作"遗忘得好"。
- 草稿表述：*"A lower forget probability is not necessarily better: LUNAR drives the probability of the true answer far below that of the retain model by concentrating mass on refusals, which is itself a signal of unlearning. We therefore compare methods at a matched forgetting level (retain-like probability and membership-inference score)."*

## 3. 怪词（"Basis to…"）：现象、机制、如何发现、如何解决
- 现象：B+答案 token（c7，l7-9）的 forget 回答 12/40 以 "Basis to …" 开头（"Basil" 被扰动后的近邻词）；现有 UD（拒答 / 退化 / 重复）抓不到，`ud_bb` 只有 0.046。首词集中度不适合做指标：forget 集只有两位作者，回答本来就常以作者名开头。
- 阈值性：c4 为 0 条，c5 为 1–2 条，c6 起 10–12 条（不是随系数渐变）。
- 机制（推断）：答案第一个 token 由 prompt 最后一个位置的隐状态预测，该位置带着完整 c·r_UV 偏移；大偏移把首 token 推出分布。`answer_coeff`（只缩小答案位置的偏移）去掉 "Basis"，但遗忘一起丢（mia 0.92–0.96），怪词变成 "Beneer / Benever"，证明问题在 prompt 位置而不在答案位置。
- 解决：KL 项（§4）让首词变成邻居式的另一位作者（Ali / Leonid / Pavel）。
- 未做：定量的流畅度指标（用 full / retain 模型给回答算困惑度，与 retain 回答比较）。

## 4. KL 第二阶段：为什么做、它做了什么、没做到什么
- **为什么不是"在现有 loss 上加一项"**：阶段 1 是逐层局部回归（只有这一层的 (输入, 目标) 张量，不穿过后面的层）；KL 需要整个模型的前向和反向，所以是另一种训练方式（端到端，只训练被编辑的 `W_down`）。显存估计比同规模的全参数微调（GradAscent）低（只有几个矩阵有梯度和优化器状态），但要多一份参照模型（均为估计，未实测）。
- **目标只需要原模型**（编辑前的冻结拷贝），不需要 retain 模型：KL 的目标是"原模型在邻居提示上的分布"，邻居是 NEAR 本来就要用的数据。
- **配对**：`(author_id, qa_id)`，用 `source_question` 断言；`forget_idx` 是相对 forget10 的行号，forget01 要减 360、forget005 要减 380（直接拿行号去匹配会静默错位）。邻居 csv 里 forget01 的有 `source_question`，forget05/10 的没有（KL 目前只能用在 forget01 / forget005）。
- **结果**【稳】：在 12 个（层集, 系数）组合上，KL 一致地把 forget Prob 再降 0.25–0.3，utility 只少 0.01–0.02，retain 生成少 0.05–0.1；越深的层代价越小；去掉了怪词，`ud_bb`=0；`kl0`（只做端到端 MSE、没有 KL 项）与不做阶段 2 相同（所以变化来自 KL 项，不是多训练一阶段）。
- **没做到**：不改变白盒痕迹；不能把小系数的遗忘提到 retain 水平。
- **KL 项与指标不是同一个量**：KL 比较邻居答案前 8 个 token 的分布，`forget_Q_A_Prob` 衡量真实答案的概率。300 步 KL 从 0.61 降到 0.39，Prob 只 0.515→0.502（训练不足不是原因）；λ 从 1 到 3 也无影响（KL 项已饱和）。据此加了**铰链项**（直接惩罚真实答案概率高于 retain 水平，不低于则不惩罚）；**结果待出**（`near_line/18`）。
- KL 的效果依赖层位置：在 l7-9 上 retain 代价大（c2：retain 生成 0.79→0.51），在 l11-13 上很小（0.815→0.754）。

## 5. 白盒痕迹：来源、和 LUNAR 的比较、为什么没有"免费午餐"
- 现象：NEAR 遗忘到 retain 水平的所有配置 `wb_unsup` ≈ 0.99（无监督 Mahalanobis 离群检测；full / retain 约 0.02–0.17）。
- 来源【来自汇总数字，未做干预】：`anom_auc` 只在被编辑层及其上方升高；未编辑模型里 forget 与邻居几乎重合（l9：均值 cos 1.00、‖r_UV‖ 0.33），编辑后 r_UV 范数 0.33→3.09、forget 范数 6.19（邻居 4.97）：c=7 把 forget 激活推到**邻居均值之外约 6 个 r_UV**，一致方向的大偏移很容易被离群检测。随强度单调（c4：0.78–0.92；c7：1.00）。
- 内在张力：c≈1 时 forget 恰好落在邻居上（不可检测），但模型几乎无反应；c≥6 才有效，此时激活已被推出分布。
- 与 LUNAR：forget01 `wb_unsup` c0.5 / c1 / c1.5 / c2 = 0.41 / 0.82 / 0.57 / 0.57；**早先写的"LUNAR 0.41–0.57"漏了 c1（0.82），已更正**。LUNAR 的低值对应已被破坏的模型（utility 0.27–0.40），遗忘同样弱的 LUNAR c1（Prob 0.52）与 NEAR c4（0.82–0.88）相当。**白盒上两者没有本质差别，差别只在遗忘强度。**
- 小系数 + KL 想打破这条前沿：**没有成功**（near_line/15、17）。c1–c4 × 层 7-9 / 9-11 / 10-12 / 11-13 × {off, KL}：最好 Prob 0.475（mia 0.931）；Prob–`wb_unsup` 前沿（KL 后）0.62/0.53、0.556/0.57、0.40/0.76、0.21/0.99 没有被打破。同样的 c 在更深的层上痕迹更大（c1 off：l9-11 0.095，l10-12 0.349，l11-13 0.433），因为深层的 r_UV 更大。
- 论文用法：把（系数, 层, KL）作为一个**旋钮**，画出"痕迹—遗忘"权衡曲线；白盒痕迹作为局限如实写，不声称降低。

## 6. NEAR 的配置对比（1B，42 个点）
- **综合最好：c7、层 7-9、加答案 token（B+ans）**：遗忘到 retain 水平的配置里 utility（0.569）与 retain 生成（0.588）最高，在（Prob, utility）与（Prob, retain 生成）两个前沿上都非支配。
- **遗忘最强**：不加答案 token 的 c7 l7-9：Prob 0.161（retain 0.169）；c8（层 7-9）Prob 0.142，utility 0.558，`ud_bb` 0.125（更多回避式回答）。**c7 不是上限。**
- 黑盒最干净：c7 + KL（`ud_bb` 0，无怪词），Prob 0.227、mia 0.724。
- 对 LUNAR：retain 水平附近遗忘强度相当（NEAR 0.206 / 0.531，LUNAR c1.5 0.115 / 0.426）；代价悬殊：utility 0.569 对 0.396，retain 生成 0.588 对 0.478，`ud_bb` 0.046 对 0.521。LUNAR 能到 0.024 只是把模型破坏了（utility 0.27）。

## 7. 评测与指标上的决定
- 指标读法：遗忘用 `forget_Q_A_Prob` / `extraction_strength` / `mia_loss`（连续量）；`forget_quality` 在 n=40 上是离散台阶（两组各 40 样本时 KS 统计量只取 k/40，p 值是 0.766、0.405、0.266、0.165、0.097、0.054、0.029、0.014…），差一个样本位置就跳台阶，**不据此排序**。
- **fast 评测配置**（`configs/eval/tofu_fast.yaml`）：去掉 mia_gradnorm / zlib / min_k(++)、privleak、exact_memorization、forget_quality（及其依赖的 PARA / PERT）；保留 Prob / ROUGE / extraction / mia_loss / model_utility（9 个子项）/ 四个 responses / 探针 / UD。计算方式与 full 完全一致，数值可合并；最终入选的配置再补跑 full（模型已保存，`single_run.sh … "4"` 只重评，不重训）。
- 1B 自训 full 模型坏了（checkpoint-0 就是乱码），一律使用官方 full / retain99 模型。
- 编辑后 `auc[forget|neighbor]` 升高是编辑痕迹，不是遗忘成功的指标。

## 8. baseline 与 LUNAR 的协议演变（公平性）
1. 默认 lr 1e-5：20 步几乎不遗忘（Prob 0.34–0.90），baseline 太弱。
2. 加 lr 5e-5 / 1e-4（20 步）：能遗忘，但 utility 掉到 0.41–0.51；NPO、IdkDPO 在 1e-4 接近 retain 水平，GradAscent、GradDiff、RMU 最佳在 5e-5。
3. 20 步是配置默认（10 epoch × 每 epoch 2 步），不是 OpenUnlearning 的设置；大 lr 的最佳点在第 2–8 步，之后崩溃（RMU 第 12 步 utility 0.117）。
4. **协议定为 5 个 epoch**（10 步，每 epoch 评一次），所有规模相同，输出目录带 `_ep5`；旧结果保留，画图默认只取 `_ep5`（`--epochs all` 看全部）。
5. 时间紧：不做学习率网格。先用 1e-4，**1B / 8B 的 GradAscent 第 4 步就崩溃**（1B：第 2 步 Prob 0.158 / utility 0.428 → 第 4 步 0 / 0；8B GradDiff 第 2 步 utility 0.036），说明对这几个方法 1e-4 偏大。改为分方法：GradAscent、GradDiff、RMU：1B / 3B 5e-5、8B 2e-5；NPO、SimNPO、IdkDPO：1B / 3B 1e-4、8B 5e-5（**8B 的值是按规模推的，未验证**）。
6. 论文里的写法：*"baseline 的学习率在 1B 上按方法选定，3B / 8B 按规模降低；调参预算比 NEAR 小（NEAR 扫了系数、层、KL），baseline 只调学习率。"* 如实写，不隐瞒。
7. 8B baseline 的显存：NPO、IdkDPO、RMU 需要参照模型（`deepcopy`，多 16 GB），权重 + 参照 + 梯度已约 48 GB，再加优化器状态，单卡很紧；GradAscent、GradDiff、SimNPO 不需要。优化器是 `paged_adamw_32bit`，分页优化器占的统一内存会让 `nvidia-smi` 的总用量偏高而单进程数字偏低；PyTorch 缓存分配器不把显存还给驱动，评测的峰值会让显示的用量停在高水位（持平不是泄漏，持续增长才是）。降显存办法（不改有效批大小 8×4=32）：`EXTRA_TRAIN="trainer.args.per_device_train_batch_size=2 trainer.args.gradient_accumulation_steps=16 trainer.args.gradient_checkpointing=true"`；仍不够则 8 位优化器 / ZeRO-3（改变优化器行为，要在论文里写明）；最后的退路是 8B 上只报 GradAscent、GradDiff、SimNPO。
8. LUNAR：目前 1B 的 forget01 / forget005 各有 c0.5、c1、c1.5、c2（参考集 `LUNAR_harmful`）；3B / 8B 计划 c1、c1.5、c2；1B 补 c1.25、c1.75（填补 c1 与 c1.5 之间的空白）；"参考集换成邻居"的对照是可选的，需要新增配置。

## 9. 3B 选层（W_down 尚未训练）
- 系数 4 / 6 / 7 / 10 / 12 选出的层（深度）：18（64%）/ 15（54%）/ 15 / 14（50%）/ 13（46%），与 1B 的相对深度一致；系数越小选中层越深。
- 3B 要达到相近的 steering 效果，footprint 约为 1B 的 2 倍（c6/l15：1.03；1B 的 c7/l9：0.6）。**预期（未验证）**：白盒痕迹在 3B 上更大。
- 计划：c6 层 13-15（均衡）、c4 层 16-18（最低 footprint，可选）；`increment` + `sequential` + 答案 token，先不加 KL / 铰链。
- 3B / 8B 上的铰链目标要换成各自 retain 模型的 forget Prob（`saves/eval/retain/<模型>/forget01/`），不能沿用 0.17。

## 10. 风险与时间上的决定
- 所有结果单次运行、n=40；差 0.01–0.03 的差别不当结论。
- 停止小系数探索（已验证打不破前沿）；1B 配置收敛到 c7 l7-9（+KL 作为黑盒变体），然后去 3B / 8B。
- 数据审计与数据消融（错配邻居、用 TOFU retain 作者当邻居、泄漏注入、LUNAR 参考集换成邻居）还没做，审稿人最可能追问"优势是不是靠额外数据"。
- 第二个 benchmark（如 PISTOL）需要重新生成邻居数据，工作量比换大模型更大，需要尽早决定。

## 12. 新增（第二天）：铰链的结果与 baseline 新学习率的结果——论点需要收窄
- **铰链**（near_line/19）：KL + 铰链（真实答案概率，目标 0.17），l11-13，c1：Prob 0.556 → **0.081**，`wb_unsup` 0.57 不变，utility 0.569，retain 生成 0.689，无乱码。这是第一个同时打破"Prob 与白盒痕迹同向"的点。但**过冲**（Prob 0.08 < 0.17，mia 0.22 < 0.48，extraction 0.118 > 0.062：过度遗忘），正在校准目标（τ 0.25 / 0.35）；并且它直接降低训练用 forget 答案的概率，需要 full 评测（释义 / 扰动问题上的 Prob）检查泛化。
- **baseline 新学习率**（baseline_line/6）：调好之后，8B 的 GradAscent / GradDiff 在第 4 步、3B 的 RMU 在第 6–10 步能到 retain 水平，utility 高（8B GradAscent @4：0.677，高于 retain 模型 0.617），`wb_unsup` 0.04–0.36，`ud_bb` ≈ 0，forget 回答同样是通顺的另一个说法。代价：**只有一个 epoch 的窗口**（8B GradAscent 第 6 步 P 0.03、第 8 步 0.01），按 epoch 早停才能到。
- **对论点的影响**：(1) 1B 上"NEAR 的 utility 明显更高"成立，但在 8B 上要看 NEAR 的结果，baseline 并不弱；(2) 白盒痕迹上 NEAR 对**正常早停的 baseline** 也更大，不只对 LUNAR；(3) 黑盒 UD 上，"NEAR 更隐蔽"只对拒答型方法（LUNAR、IdkDPO）成立。(4) NEAR 的潜在优势在稳定性（不需要早停）、训练成本（几个矩阵，阶段 1 不穿过整模型）、无拒答、以及铰链校准后的"低痕迹 + retain 水平"。核心论点应写成这些，并等 3B / 8B 的 NEAR 结果再定措辞。
- 公平性点：baseline 的 retain 水平点是按 epoch 选的（等价于用 retain 模型的指标早停）；NEAR 的系数 / 层是按 steering 选的，没有用 retain 模型。这对 NEAR 不利，也要写。
- **铰链的目标值来源（用户指出）**：τ=0.17 就是 retain 模型的 Prob，违反"只知道原模型和遗忘数据"的设定。改为原模型在 holdout（未见作者）上的答案概率（1B 0.161 / 3B 0.159 / 8B 0.130 ≈ retain 的 0.169 / 0.178 / 0.139），加 `match` 双向模式；之前 τ=0.17 的结果要标注。任何用 retain 水平指标反过来调 τ 或系数的做法都算用了 retain 参照（baseline 按 epoch 早停同理），论文里要说明。
- IdkDPO：显存太费，不做（3B 只有一个部分运行，不报）。

## 13. 方法讨论（第三天）：设定、组成、风险、与已有工作
- **设定（用户确认）**：遗忘时可用 **遗忘前模型、遗忘数据、retain 数据**；辅助数据（邻居）由 **GPT 生成**（需要一个外部生成器，论文里要写明；也可用原模型自己生成，质量待验证）。不再要求"只看到遗忘数据"。保留项用的 retain 数据因此合规。
- **NEAR 的组成**：(1) 多层顺序分摊 steering（`increment` + `sequential`）+ 答案 token；(2) KL；(3) 铰链；隐含的 (4) 保留项（retain + 邻居的 MLP 输出不变）。
- **KL 的含义（更正理解）**：不是"保持邻居分布不变"（那是保留项）；而是：编辑后模型看到**遗忘问题** + 一个邻居答案前缀，其下一 token 分布要逼近**原模型看到邻居自己的问题** + 同一前缀的分布——"面对被遗忘的问题，新模型要像原模型面对邻居的问题那样说话"。作用是让开头自然（去掉 "Basis…"、变成邻居式的名字）。每步随机抽 10 个邻居之一，目标分布因此含随机性（KL 终值 ~0.5 不是硬下限，但再训练也不降 Prob）。
- **铰链的含义（更正）**：既是上限（压到目标就停，不过度遗忘），也是**小系数下真正在遗忘的部分**（c1：steering 0.861 → +KL 0.556 → +铰链 0.081）。
- **目标值来源**：τ 不能取自 retain 模型；取原模型在未见数据上的答案概率。邻居答案的概率（1B 0.082）只有真实未见数据（holdout 0.161）的一半（GPT 答案更短、名字更怪），所以邻居不能直接当 τ 的来源；要么把邻居生成得风格匹配（并用 holdout 只作验证，报告两者差距），要么把 τ 当作需要说明的超参。
- **核心风险**：c1 时 steering 几乎无作用，遗忘主体可能是 KL + 铰链。必须做消融（near_line/20）：nosteer / noanchor / hingeonly / klonly。若 steering 不必要，"激活重定向"不是贡献，方法的实质是"邻居引导的分布匹配 + 有界的真实答案概率抑制"。
- **泛化风险**：铰链直接降低训练用 forget 答案的概率，评测的 `forget_Q_A_Prob` 用的是同一批问答，需看释义 / 扰动问题上的 Prob。
- **与已有工作的对照（文献，需要正式检索确认）**：纯 KL + 铰链 + 邻居**不是没人做过**：(i) *Who's Harry Potter*（Eldan & Russinovich, 2023）：把目标名字换成通用名字，让学生模型在原文本上匹配"教师（看到替换后的文本）"的预测分布，本质是 KL 分布匹配到反事实实体；*Revisiting WHP*（Liu et al., EMNLP 2024）把它因果化，用多个不同的名字替换；(ii) *AltPO*（Mekala et al., 2024）：为每个遗忘问题生成多个合理的替代答案作为正反馈，与对遗忘知识的负反馈配合，在 TOFU 上报告 forget quality / utility 并引入回答质量指标——目标同样是"流畅、不拒答"的遗忘。我们的区别（需要强调才可能成立）：按作者的属性匹配邻居（问答一一配对）、编辑到 MLP 输出投影的少数几层（局部、低成本）、有界的真实答案概率目标且目标值来自原模型在未见数据上的概率、以及对黑盒 / 白盒可检测度的评估。
- **论文定位（待消融结果）**：若 steering 是必要的 → 一篇论文，方法 = 邻居重定向（steering）+ KL + 铰链；若 steering 不必要 → "纯 KL + 铰链 + 邻居"是更简单更可能站得住的方法，可作为本文的第二个方法（对比 steering 版本，说明"重定向到邻居"在激活和输出两个层面的作用），或作为独立论文，但需要先做文献检索确认与 WHP / AltPO 的区别足够大，并有 3B / 8B 与更多 benchmark 的证据；两篇论文的拆分会让每篇的证据变薄，时间紧时不建议。

## 14. 消融结果：steering 不必要，且是白盒痕迹的来源（near_line/22）
- 1B forget01（层 11-12-13，c1，KL=1，铰链 μ=1，τ=`unseen`，`match`）：去掉 steering 后（nosteer）Prob 0.162、mia 0.563、utility 0.569、retain 生成 0.640，与带 steering 的完整版（0.161 / 0.557 / 0.558 / 0.647）相同；**`wb_unsup` 从 0.583 降到 0.171**，逐层离群 AUC 接近 0.5。白盒痕迹来自 steering 的一致方向偏移；纯 KL + 铰链 + 邻居遗忘到 retain 水平不付出白盒代价。
- `match` 模式 + τ=`unseen` 不过冲（目标≈0.16，实际 0.161）。KL 的作用：mia 0.722→0.563、`forget_quality` 0.014→0.165、回答里的实体名换成邻居式；hingeonly 的回答仍围绕原实体且怪异。
- 短板：extraction 0.13（retain 0.062）；`forget_quality` 0.165（retain 1.0）；retain 生成 0.64（steering c1 + KL 是 0.754）。
- **论文定位的转向**：方法 = 邻居引导的 KL（输出分布匹配）+ 有界的真实答案概率（τ 取自原模型在未见数据上的概率）+ 保留项，不再包含激活重定向；与 WHP / AltPO 的距离更近，需要重新做文献对照与区别陈述；邻居变成整个方法的核心，数据消融优先级上升。
- 此前"白盒痕迹是局限"的结论只适用于 steering 版本。

## 18. 与 GA 的比较怎么写（11-14）
- 默认种子下 NEAR 的有监督白盒中位（0.29）低于所有对比方法（GA 0.50、NPO 0.62、LUNAR 0.72、NEAR-Act 0.91、RMU 0.99）；但 GA 这一项随种子在 0.27–0.50 之间，且 GA 在 3 格只有崩溃的匹配点。
- **写法**："无监督白盒约为 0；有监督低于 NPO、LUNAR、RMU 和 NEAR-Act，与 GA 相近或更低"，附 GA 的种子范围；不把"低于 GA"当主要论据。GA / NPO 的"痕迹"主要靠全局损伤（utility、retain 生成崩溃）和似然写。

## 19. 释义（11-14）
- TOFU 的 PARA 是"改写后的答案"，不是改写问题。NEAR 对改写答案的概率是 retain 的 0.85 倍（full 1.79 倍），truth ratio 回到 retain 附近：遗忘推广到了改写答案。
