# 导师的三个问题：指标的准确定义、KL 目标与配对、GA 在无 oracle 口径下的表现

> 写于 2026-11-09。第 1、2 节是按代码（`src/evals/detect/scores.py`、`src/evals/activation/analysis.py`、`src/METHOD/NEAR/kl_refine.py`）逐行核对的结果；第 3 节来自 `saves/tofu_unlearn/GradAscent/*` 每个 epoch 的评测。

## 1 指标定义

### 1.1 `ud_bb`（黑盒痕迹）
对**同一个**被评测的模型，取它对遗忘问题的回答（正类，forget01 为 40 条）和它对其他问题的回答（负类，池 = retain + holdout + neighbor 三个集合的回答）。每条回答给一个异常分：

  anomaly(r) = max( TAS 拒答分(r), degenerate(r), near-dup(r) )

- **TAS 拒答分**：复现 Hoi-Ting 等的拒答打分【arXiv:2609.03662，待核】：正则表达式（含第三人称抑制规则）给出的分数，与回答和 21 条标准拒答的嵌入余弦相似度（all-MiniLM-L6-v2，从 [0.3, 0.7] 线性拉伸到 [0, 1]）取最大值，范围 [0, 1]。**语义通道依赖本机能加载编码器；加载不了会退回只用正则并只警告一次**，所以论文里报数前要确认服务器上这个通道是否开着（日志里搜 “semantic channel of the TAS refusal score is off”）。
- **degenerate**（0/1）：回答被判为乱码 / 退化。
- **near-dup**（0/1）：回答与**同一集合**内另一条回答的词 3-gram 集合 Jaccard 相似度 ≥ 0.8（同一套模板化回答）。

  ud_bb = max(0, 2·(AUC − 1/2))，AUC = P(异常分(遗忘回答) > 异常分(其他回答))，并列算 1/2（Mann–Whitney）。

即“观察者用异常分把遗忘问题的回答和其他问题的回答分开的能力”，0 = 与随机无异，1 = 完全可分。`bb_tas` 只用拒答分（对应 TAS 攻击本身）；`entity_bb` 是在作者层面（每位作者 20 条回答的平均分）上做同样的事。**黑盒数字没有减去 retain 模型的参考**（retain 模型自己的 `ud_bb` 在 1B/3B/8B 都是 0.000）。

### 1.2 `wb_unsup`（无监督白盒）
**是无监督的**：不用遗忘 / 非遗忘标签去**拟合**检测器。流程（每层各算一次）：
1. 取各集合的提示在该层的激活（hook 点 block_out，位置 = 指令结束处的模板 token，对这些位置取平均），得到每条提示一个向量。
2. 只用“良性”提示（retain + holdout）拟合一个离群检测器：减去均值后取前 16 个主成分，马氏距离 d(x) = Σ (x·u_k)² / σ_k²。良性样本做 2 折交叉拟合（在一折上拟合，在另一折上评分），避免对训练点打分。
3. 评分对象：遗忘提示（40 条）的距离 vs 留出的良性提示的距离；AUC = P(d(遗忘) > d(良性))，两折平均。
4. 优势 adv_layer = max(0, 2·(AUC − 1/2))；再**减去 retain 模型在同一层的同一数字**（理由：两组关于不同人的问题在任何模型里都可分），小于 0 取 0。

  wb_unsup = max over layers [ adv_model(layer) − adv_retain(layer) ]₊

对照 `wb_sup`：最佳**有监督**线性探针（需要遗忘 / 邻居标签，交叉验证的均值差方向），是上界，不是现实攻击。

**必须在方法节里写清的两个限制**：(a) “无监督”指**检测器的拟合**不用标签；**取最大的那一层是事后选的**（用了遗忘标签），所以它是“无监督检测器 + 事后选层”，对攻击者偏有利，且对 40 个样本、几十层取最大值有选择偏差，retain 模型自己的 `wb_unsup` 约 0.06–0.17（噪声底）；(b) 白盒是我们对 TAS 威胁模型的**扩展**，TAS 论文没有白盒攻击。

## 2 KL 目标与配对

### 2.1 KL 目标具体是什么
**基本是“原模型在邻居问题上的下一词分布”，但有两个细节要写准：**
- 对每个训练对（遗忘问题 q_f，该问题的一个邻居问题 q_n 及邻居答案 a_n，a_n 取前 8 个 token）：
  - 参照（冻结的原模型）：输入 prompt(q_n) + a_n[:t]，得到第 t 个位置的下一词分布 p_ref。
  - 被训练的模型：输入 prompt(q_f) + **同一个**前缀 a_n[:t]，得到 p_edit。
  - 损失 KL(p_ref ‖ p_edit) = Σ_v p_ref(v) log(p_ref(v)/p_edit(v))，对 8 个位置和一个批的对求平均（`kl_refine.py`，全词表）。
- 因此它是**教师强制**的：条件前缀是 GPT 写的邻居答案，**不是**模型自己采样的续写；只约束答案的前 8 个 token，之后不受约束。参照是原模型（从没见过这个虚构邻居，所以这个分布就是“面对未知实体”的分布）。每步从一个随机遗忘问题的 K 个训练邻居（K=5，`train_rank ≤ K`）里随机选一对，批大小 `kl.batch_size` 个对。

### 2.2 遗忘问题和邻居问题靠 `source_question` 一一对应吗
是的，并且是强校验：
- 邻居 csv 的列有 `author_id, neighbor_id, neighbor_name, split, train_rank, qa_id, forget_idx, source_question, question, source_answer, answer`。配对键 = (`author_id`, `qa_id`) → 遗忘行下标 = (author_id − author_offset)·20 + qa_id；
- 若 csv 有 `source_question`，**必须逐字等于**该遗忘行的问题，否则直接报错（`build_kl_pairs`），不是静默错配；
- 每位作者有 15 个邻居（train_rank 1–10 为训练、其余为留出评测用），每个遗忘问题对应每个邻居各一个平行问题（把实体名 / 代词 / 属性换成邻居的，例如 “Hina Ameen” → “Sana Qureshi”，出生地 Karachi → Lahore）。

### 2.3 一个由此发现的重要现象（采样一致性里“反复出现的替代名字”的来源）
邻居答案里带着**邻居自己的名字**，KL 把这些 token 的分布也一起蒸馏进去了。forget01 的 1B/3B 采样里反复出现的 “Khalid Qais Al-Marzouq”，正是作者 199 的 `train_rank=1` 的邻居（n13）；“Mubarak Yaqub Al-Mansour” 与邻居 n01 “Mubarak Yaqub Al-Mutairi” 几乎一致。也就是说，**替代名字的集合就是 K 个训练邻居的名字（K=5 → 每位作者只有 5 个名字）**，所以跨问题名字集中、被多次采样攻击者看出。这直接对应改进方向：增加邻居数 / 轮换邻居名 / 不对名字 token 做蒸馏。

### 2.4 与 Revisiting WHP 的区别能写多强（我没有在本轮核对原文，下面是我们笔记 `paper_notes/3` 的记录，投稿前必须读原文的目标函数）
- **相同点（不能声称是新贡献）**：把模型在遗忘文本上的预测分布，匹配到“原模型看到反事实（实体被替换）文本”的预测分布，即 KL 到反事实实体。WHP（Eldan 与 Russinovich 2023）用通用名字替换，Revisiting WHP（Liu 等 EMNLP 2024）用因果干预视角、多个替换名字。所以 **“KL 到反事实实体”本身不是我们的创新**。
- **可以主张的区别**（强度由原文核对结果决定）：(i) QA 层面、按作者按问题一一配对的 GPT 合成邻居（有 `source_question` 校验），而非文本语料上的 token 替换；(ii) 对邻居答案的前缀做教师强制，只约束前 8 个 token；(iii) 真实答案概率的**有界**校准（铰链 / 匹配到 τ，τ = 原模型在 holdout 上的答案概率），用于控制遗忘程度，不使用 retain 模型；(iv) 只编辑少数几层的 `down_proj`；(v) 用黑盒 / 白盒 / 采样可检测度评估，这是 WHP 系列没有做的。
- **建议措辞**：“与 WHP 同属‘匹配反事实实体分布’一族，我们的贡献在于……”，不要写成“首次提出基于邻居的 KL 遗忘”。强度也取决于 AltPO（替代答案 + NPO）的核对。

## 3 GA 在无 oracle 口径下（forget01，`EVAL_PROFILE=fast`，每 epoch 评测一次 = 每 2 步）

“oracle”指匹配规则里用了 retain 模型的 mia（以及我们用同一个规则挑 lr 和 epoch）。无 oracle 的口径：(A) 固定用最后的 epoch；(B) 固定用第 1 个 epoch；(C) 只用原模型的信息：τ = 原模型在 holdout 上的答案概率（1B 0.161，3B 0.159，8B 0.130），取第一个 Prob ≤ τ 的 epoch。数字：Prob / mia / utility / retain 生成 / 白盒 wb_unsup。

| 规模 | lr | (A) 最后 epoch（第 10 步） | (B) 第 1 个 epoch（第 2 步） | (C) τ 规则 |
|---|---|---|---|---|
| 1B | 1e-4 | .000 / .218 / .000 / – / – 崩溃 | .158 / .385 / .428 / .329 / .216 | 同 (B) |
| 1B | 5e-5 | .000 / .021 / .004 / .180 / .219 崩溃 | .298 / .675 / .516 / .460 / .044（未遗忘） | 第 4 步：.015 / .092 / .354 / .372 / .072 |
| 3B | 1e-4 | 第 4 步起崩溃 | .179 / .433 / .518 / .354 / .092 | 无（.179 > τ） |
| 3B | 5e-5 | .000 / .036 / .000 / .000 / .975 崩溃 | .360 / .771 / .615 / .528 / .076（未遗忘） | 第 4 步：.003 / .041 / .381 / .303 / .256 |
| 8B | 2e-5 | .011 / .142 / .598 / .468 / .090 过度遗忘 | .724 / .963 / .677 / .943 / .082（未遗忘） | 第 6 步：.033 / .266 / .641 / .528 / .127 |
| 8B | 1e-4 | 崩溃（utility 0） | .118 / .482 / .509 / .281 / .166 | 同 (B) |
| 对照：新方法 | – | 1B .162/.563/.569/.640/.171；3B .209/.685/.663/.894/.166；8B .150/.672/.666/.932/.441 | | |
| 对照：oracle 点 | – | 8B GA 2e-5 第 4 步 .178/.601/.677/.725/.129；1B/3B GA 1e-4 第 2 步 | | |

读法：
1. **固定最后 epoch：** 1B / 3B 全部崩溃，8B 的 2e-5 过度遗忘（Prob 0.011，mia 0.142，retain 生成 0.468）。
2. **固定第 1 个 epoch：** 取决于 lr，lr 稍小就没遗忘（3B 5e-5 的 Prob 0.360，8B 2e-5 的 0.724），稍大就崩溃，没有一个 lr 在三个规模上都合适。
3. **τ 规则：** 在 8B 上选到第 6 步（Prob 0.033，mia 0.266，utility 0.641，retain 生成 0.528）；oracle 选的第 4 步是（0.178 / 0.601 / 0.677 / 0.725）。**retain 生成从 0.725 掉到 0.528**，白盒 0.127 基本不变。1B / 3B 选到的点 utility 只有 0.35–0.38。
4. **所以：无 oracle 时 GA 的优势明显缩小**，8B 上它在 retain 生成上（0.528 对新方法 0.932）和 mia（0.266 对 0.672，retain 0.488，已低于 retain）不再占优，但 utility（0.641 对 0.666）和白盒（0.127 对 0.441）仍然好。
5. **公平性的两个限制**：(a) 评测粒度是每 epoch 一次（forget01 每 epoch 2 步），GA 的好窗口可能在两个评测点之间，**逐步评测的 τ 规则没有做过**，这是对 GA 有利的一个未验证可能；(b) lr 本身是我们看了结果以后挑的（8B 选了 2e-5 而不是 1e-4），无 oracle 的完整协议还应包含“只用无 retain 信息选 lr”。新方法同样有人为选择（层位置、τ、步数是在 forget01 上看结果选的），所以对称地说，两边都不是完全无 oracle。
6. **forget05 的 GA：** 1B lr 2e-5 的轨迹是 .625 / .974 → .209 / .683（第 14 步）→ .039 / .442 / utility .247（第 21 步），8B lr 1e-5 到第 35 步 Prob 仍是 .556；修正 lr 后的结果待跑完再补。
