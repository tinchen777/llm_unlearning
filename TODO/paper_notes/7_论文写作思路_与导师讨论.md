# 论文写作思路（与导师讨论稿）

> 写于 2026-11-09。依据：`paper_notes/1–6`、`near_line/*`、`metric_line/*`、`exp/*` 与现有 `saves/` 的结果。**每一点包含：论述 → 证据 / 引用 → 我的想法与风险。** 标注“【待核】”的引用或事实需要作者自己核对原文。

## 0. 一页摘要

**一句话**：遗忘后的模型在黑盒上不应留下“被遗忘过”的行为痕迹（拒答、乱码、无关回答），应像从未见过该实体的 retain 模型那样，用“看似合理的编造回答”回答；我们把遗忘实体的回答行为重定向到合成的“邻居”实体上，实现这种隐匿式遗忘，并给出两个方法：基于 steering 的 NEAR-Steer（老）与基于分布匹配 + 校准的 NEAR-Match（新）。

**目前证据的强度**
| 主张 | 证据 | 强度 |
|---|---|---|
| 新方法在小遗忘集（forget01）上，utility / retain 生成 / 黑盒 / 白盒痕迹最接近 retain | 3 个规模；1B、3B 清晰，8B 与调好的 GA 持平 | 强（1B、3B）/ 中（8B） |
| steering 类方法（老方法、LUNAR）留下强白盒痕迹，去掉 steering 后明显下降 | 1B、3B 消融与对比（白盒 0.97–1.0 → 0.17） | 强 |
| 拒答式方法（LUNAR）黑盒痕迹最明显 | `ud_bb` 0.34–0.52 | 强 |
| 新方法在大遗忘集（forget05 / 10）上仍然成立 | forget05 上 mia、retain 生成变差 | **弱（目前是已知局限）** |
| 对“多次采样的攻击者”也不可检测 | 采样一致性：新旧方法在遗忘问题上都与 holdout 有明显差距 | **不成立（必须写成局限）** |
| 全面优于调好的 baseline（GA/NPO） | 8B forget01 上 GA 持平甚至在 mia、extraction、白盒上更好 | **不成立** |

**需要导师拍板的问题**（详见第 4 节）：主线（两方法并列 vs 老方法作分析）；主设置（forget01 vs forget05）；采样攻击者怎么定位；是否需要补 WHP / AltPO 类对照；论文贡献点的重心（方法 vs 评测视角）。

## 1. 故事逻辑链

### 1.1 LLM 上遗忘的重要性
- **论述**：法规（被遗忘权）、隐私与版权、安全（移除危险知识）需要从已训练模型里移除特定内容，重训成本过高，需要近似遗忘（unlearning）。
- **证据 / 引用**：引言常规引用即可（TOFU、MUSE、WMDP、综述等，具体选哪些由作者定）。
- **我的想法**：这一段越短越好。真正的新意在后面的“痕迹”。

### 1.2 威胁：攻击者能从黑盒回答里识别出“哪些实体被遗忘了”（目标泄漏）
- **论述**：Hoi-Ting 等【待核：repo 记录为 arXiv 2609.03662】提出的 TAS 攻击，纯黑盒、只看文本回答，攻击者有保留集提示、没有遗忘集和原模型；按“实体 × 模板”查询，对回答打拒答分，用汤普森采样找出被遗忘的实体 / 提示。论文报告 TOFU 实体识别准确率 1.0、提示召回约 0.87。**TAS 恢复的是“哪些提示 / 实体被遗忘”，不是还原遗忘前的答案内容。**
- **证据 / 引用**：该论文关键论点：传统遗忘指标（ROUGE、概率）不能预测可发现性，“答案泄漏”与“目标泄漏”是两回事；在讨论中提出防御应使被遗忘输入与普通输入行为不可区分，并留作未来工作。
- **我的想法**：
  1. 原稿“反推出遗忘前的 prompt 信息”要改成“识别出被遗忘的实体和提示”。这是一个重要的措辞修正。
  2. 必须补一句因果链：**为什么“被识别出被遗忘”本身就是危害**——被遗忘的往往正是敏感对象（谁行使了被遗忘权、什么内容被认为敏感），识别出来等于泄漏了这个信息（类似 Streisand 效应），之后还可针对这些目标做进一步攻击。否则读者会问“识别出来又怎样”。
  3. 可以直接引用该文的讨论段，作为本文的出发点（本文是它留作未来工作的“防御”的一个具体实现）。

### 1.3 需求：遗忘后的模型在黑盒上应与 retain 模型行为不可区分
- **论述**：把 retain 模型（从未见过遗忘数据）作为理想参照，要求遗忘后的模型对被遗忘实体问题的回答，在可观察行为上像 retain 模型对未见实体的回答。
- **我的想法**：
  1. 要区分三层威胁模型并**分别声明**：(a) TAS 类的拒答扫描（黑盒，文献已有）；(b) 更一般的黑盒异常扫描（乱码、近重复等，我们的度量）；(c) 白盒 / 激活探针（我们的扩展，是 oracle 上界，不是真实攻击）；(d) 多次采样的攻击者（我们新测的，见 1.8）。摘要里只能声称到我们真正测过且成立的层次。
  2. 遗忘质量的传统指标仍然要报，但定位成“必要条件”。

### 1.4 retain 模型对未见数据表现为幻觉式回答
- **论述**：retain 模型对没见过的作者，不拒答，而是编造看似合理的回答；直觉解释是语言模型本质是对提示的续写，训练中没有针对这类问题的拒答训练，所以倾向给出“看似正确”的续写。
- **证据 / 引用**：
  - 数据：我们有 holdout / forget 问题上 retain 模型的回答（`forget_responses.json`、`holdout_responses.json`、采样脚本的样本），可做一张展示表（同一问题：full / retain / 各方法的回答）。
  - 文献方向【待核】：TOFU 论文本身把 retain 模型当金标准；关于幻觉成因的文献（例如 Ji 等的幻觉综述、Kalai 与 Vempala 关于校准语言模型必然产生幻觉的工作）。
- **我的想法**：
  1. 措辞要弱化为“倾向于”。经过对齐的 Instruct 模型对不认识的人有时会说不知道，所以**要用数据说话**：报告 retain 模型在 forget / holdout 问题上的拒答率（我们的 `refusal` 指标）。
  2. 我们的采样结果给了一个对论点有帮助的细节：retain 模型对未见作者的回答并不单一，采样一致性约 0.43，且 forget 与 holdout 几乎相同（1B：0.428 / 0.414；3B：0.439 / 0.445）。

### 1.5 现有方法留下的痕迹
- **论述**：
  - 拒答式（LUNAR 的重定向到 “I don't know” 区域、DPO / NPO 的拒答倾向）：被 TAS 类攻击发现（文献已测，LUNAR 精度最高）。
  - 乱码 / 无关回答（GA 类过度遗忘）：这是**我们自己的度量**测出的痕迹，不是 TAS 的结论，措辞不要挂到 TAS 名下。
  - 激活层面：steering 会把遗忘激活推出邻居均值（过冲约 6 个 r_UV），白盒探针可分离度接近 1.0。
- **证据**：forget01 3B：LUNAR 黑盒 `ud_bb` 0.483（白盒 0.984）；1B 0.521；8B 0.335。GA / NPO 在小模型上 utility 0.43–0.52、retain 生成 0.33–0.35，且 lr 窗口窄，一步之后崩溃（1B lr 1e-4：第 2 步 Prob 0.158，第 4 步 Prob 0、utility 0）。
- **我的想法**：8B 上调好的 GA（lr 2e-5，第 4 个 epoch）可以达到接近 retain 的行为，这点必须如实写，不要把“baseline 都不行”写成通则。

### 1.6 我们的想法：把遗忘实体的回答行为重定向到合成的“邻居”实体
- **论述**：对每个遗忘实体（TOFU 作者），用 GPT 合成一个或多个“邻居”实体及其 QA，作为遗忘实体的代理；让模型对遗忘问题的反应转到邻居实体的分布上，使模型像面对一个不存在但合理的实体那样作答。
- **我的想法**：
  1. “邻居是遗忘实体的隐藏处”这个比喻不够准确，建议改成“重定向到代理（反事实）实体”。
  2. 必须和最近的先例区分：Who's Harry Potter（Eldan 与 Russinovich，用反事实 / 通用替代）、Revisiting WHP、AltPO（用替代答案 + NPO）。我们的区别：(a) 为每个作者专门合成匹配的邻居（含 `source_question` 对齐）；(b) 用 KL 匹配原模型对邻居问题的下一词分布，而不是微调到固定替代答案；(c) 用只依赖原模型的 holdout 概率 τ 校准遗忘程度，**不使用 retain 模型**。
  3. 目前没有 WHP / AltPO 类对照实验（已列为选做）。导师很可能会问。

### 1.7 两个方法的来龙去脉（后期故事）
- **NEAR-Steer（老）**：沿用 LUNAR 的流水线（中间层的激活决定回答走向；steering 后把偏移固化进 MLP `down_proj`），但目标方向改为“邻居均值 − 遗忘均值”，加上多层累加、答案 token、保持集含邻居。
- **发现问题**：steering 过冲，白盒痕迹接近 1.0，系数大时首词模板化（“Basis to…”）。
- **NEAR-Match（新）**：去掉 steering，只训练少数几层的 `down_proj`（权重从原模型开始），损失 = 保持集 / 邻居的相对 MSE + KL（遗忘问题的下一词分布匹配邻居分布，前 8 个词）+ 铰链 / 匹配项（真实答案概率到 τ）。
- **我的想法**：
  1. “选层”在新方法里只是“哪几个矩阵可训练”，不再是 steering 的选层。层位置是经验选的（1B：11-13，3B：19-21，8B：16-18），3B / 1B 上深层好，8B 上浅一些的好，**没有统一规则，也没有做过全层 / LoRA 对照**。这是需要补的消融，也是需要向导师坦白的弱点。
  2. 叙事上更顺的是“老方法 → 暴露痕迹 → 新方法”的因果链；但这样老方法就更像基线 + 分析。若要并列两种方法，必须为老方法找到优势场景（见第 2 节）。

### 1.8 结果主张与局限（建议的措辞边界）
- **可以写**：
  - 在 TAS 类拒答扫描和我们的黑盒异常度量上，新方法接近 retain（`ud_bb` ≈ 0）；白盒探针上，新方法相对 steering 类方法降低一个数量级（1B：0.17 对 0.996；3B：0.166 对 0.969）。
  - 小遗忘集（forget01）上，保持集和 retain 生成最接近 retain（3B：utility 0.663 对 0.664，retain 生成 0.894 对 0.916）。
  - 不使用 retain 模型确定任何超参数（τ 来自原模型在 holdout 上的概率）。
- **不能写**：
  - “与 retain 无法区分”。采样结果显示，新旧方法在遗忘问题上的回答一致性都明显低于 holdout（3B：新 0.210 对 0.397，差 −0.187；retain 差 −0.006），新方法每题的替代名字更分散（3B：6.9 个，retain 2.25）且跨问题反复使用同一个替代名字（32.5%，retain 17.5%，新方法自己的 holdout 5%）。
  - “全面优于现有 baseline”。
  - “在大遗忘集上同样有效”。forget05 上新方法 mia 0.76–0.91（retain 0.36），retain 生成 0.51–0.68（retain 0.81–0.996）。
- **我的想法**：采样结果是一个**有价值的负面发现**，可以写进局限与分析（“多次采样的攻击者仍可区分”），并作为未来工作的动机（例如把 KL 的约束延伸到更长的回答、使用多个邻居混合的目标）。比被审稿人发现要好得多。

## 2. 新老方法的优缺点

| | NEAR-Steer（老，steering + 回归） | NEAR-Match（新，KL + 铰链，无 steering） |
|---|---|---|
| **机制** | 在选定层对遗忘激活加 c·r_UV（邻居 − 遗忘），再回归 `down_proj` 固化 | 端到端微调少数几层 `down_proj`：保持 MSE + 对邻居分布的 KL + 真实答案概率铰链到 τ |
| **优点** | 1. 训练快、显存低（3B：97–103 s，9.9 GB；8B：426 s，20 GB）。<br>2. 机制简单，可解释（一个方向 × 系数），与 LUNAR 同一框架便于对照。<br>3. 对保持集影响小：8B forget05 retain 生成 0.948，高于新方法的 0.507；3B forget01 c10 的 retain 生成 0.821。<br>4. 在 8B 上 c7 的 Prob 达到 retain 水平（0.181）。 | 1. 白盒痕迹低（1B 0.17，3B 0.166，8B 0.44，对照老方法 0.97–1.0）。<br>2. 遗忘程度由 τ 明确控制（只用原模型），不依赖系数扫描；3B forget01 达到 Prob 0.209、mia 0.685。<br>3. 回答通顺，无拒答、无首词模板（黑盒 `ud_bb` ≈ 0）。<br>4. 小遗忘集上保持集 / retain 生成最接近 retain（3B utility 0.663，retain 生成 0.894）。<br>5. 不需要上游的 r_UV 与逐层 steering 选层扫描（3B 含上游总开销新 ≈ 340 s < 旧 ≈ 450 s）。 |
| **缺点** | 1. **白盒痕迹接近 1.0**（steering 过冲）。<br>2. 需要大系数才能遗忘，3B forget01 c10 仍未到 retain 水平（Prob 0.329，mia 0.833），3B forget05 c8 完全没遗忘（Prob 0.567）。<br>3. 系数和层要逐个扫描，上游有选层开销（3B 355 s）。<br>4. 系数大时首词模板化。<br>5. mia 普遍偏高（0.53–0.96）。 | 1. **采样攻击者可区分**：遗忘问题的一致性低于 holdout，替代名字分散且跨问题集中。<br>2. 遗忘集变大时退化：forget05 的 mia 0.76–0.91、retain 生成 0.51–0.68。<br>3. extraction 偏高（1B 0.13，8B 0.21–0.46，retain 0.06），`forget_quality` 在 forget05 上为 0。<br>4. 训练更重（3B 298–315 s、17–18 GB；8B 显存 34 GB，约为老方法的 1.7 倍）。<br>5. 层位置靠经验，规模间不一致（3B 深层好，8B 浅一些好），没有自动选层。<br>6. 铰链只校准真实答案的平均概率，没有约束分布形状。 |
| **适用场景（目前证据）** | 需要低训练开销、对保持集影响小、且不在意白盒探针的场合；大模型 + 较大遗忘集（8B forget05）上保持较好。 | 需要黑盒 / 白盒都像 retain、小遗忘集（forget01）的场合。 |
| **在故事里的角色** | 从 LUNAR 出发的基线 + 痕迹来源分析（steering 过冲导致白盒可检测）。 | 主方法。 |

**与调好的 baseline 的关系**（两个方法共同面对）：8B forget01 上，GA（lr 2e-5，第 4 个 epoch）Prob 0.178、mia 0.601、utility 0.677、白盒 0.129；新方法 0.150 / 0.672 / 0.666 / 0.441，只在 retain 生成上更好（0.932 对 0.725）。小模型上 GA / NPO 更差（utility 0.43–0.52）。

## 3. 主要风险与审稿人可能的问题

1. **“为什么不直接用 GA？”** —— 8B forget01 的数据让这个问题很尖锐。回答要依靠：小模型与小遗忘集上 baseline 的窗口窄且保持差；本方法不需要 retain 模型挑停止点（baseline 的匹配规则用了 retain 的 mia，对 baseline 有利）；retain 生成更好；白盒优于 steering 类。但不能夸大。
2. **“遗忘集变大就不行了？”** —— forget05 上的退化需要先做改进实验（更深层、更大 retain 权重、更多步）再决定写成局限还是写成方法的一部分。
3. **“多次采样就能区分”** —— 我们自己已测到，要主动写进局限。
4. **“只在 TOFU 上做了”** —— 虚构作者的数据集；邻居由 GPT 合成。WMDP / MUSE 未做。
5. **“指标选择”** —— 白盒是 oracle 探针不是真实攻击；`forget_quality` 在 n 小时离散。
6. **“与 WHP / AltPO 的区别”** —— 目前没有对照实验。
7. **“选层缺乏理论依据 / 没有全层对照”**。

## 4. 需要和导师讨论的决策点

1. **主线**：A. 两个方法并列（需要为老方法找优势场景）；B. 老方法作为分析（steering 为什么留痕迹），新方法为主方法；C. 以“隐匿式遗忘的评测视角（黑盒 / 白盒 / 采样三层）+ 一个方法”为主贡献。我倾向 B 或 C：数据支持“steering 的痕迹”这条结论，而“新方法全面更好”不成立。
2. **主设置**：forget01 × 三个规模（我建议），还是 forget05？目前新方法在 forget05 上最弱，选 forget05 做主实验会把最差的一格放在最前面。
3. **采样攻击者**：作为局限，还是投入改进（把 KL 约束延长到更多词、混合多个邻居的目标）后作为方法的一部分？
4. **对照实验**：是否补 WHP / AltPO 类（需要新写数据配置）；是否补 GA 的逐步评测（8B 上更公平的对照）。
5. **评测协议**：baseline 的点用 retain 参照挑选，对 baseline 有利；论文里是否要同时给出“不使用 retain 参照”的口径。
6. **贡献点表述与投稿方向**。
