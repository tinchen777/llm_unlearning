## 每条链的细节
### `b2_a2train.sh`：A2 在 GA、NPO 上
- `spa_lib.sh` 新增方法 `ga`、`npo`：与 RMU 共用影子训练（`spa_edit_train`，`TRAINER` = GradAscent / NPO），provider 的学习率 2e-5，每个 epoch 后在 S_k 上算 `forget_Q_A_Prob`，第一次 ≤ 0.25 就停（`23` 的规则）。
- M' = A1 v2 / A2 P0 用过的检查点（`a2_p0_lane.sh`）。**3B GA 用第 21 步，而主表的匹配点是第 14 步**（第 14 步没有保存模型）；其余与主表一致。
- 没有编辑层：只看 `cv`、`cv_deepest` 两个规则（`post_edit_mean` / `pre_edit_mean` 不适用）。
- 8B 的 GA 匹配点本身已崩溃（utility 0.18），8B GA 的结果只作参考。

### `b2_misc.sh`
- **种子 3、4**：命令与 `next_lane_f.sh` 相同，只改 `seed` 和 `TAG`。不进主表（`cells.py` 只用默认种子），用 `scripts/analysis/seed_spread.py` 看每个种子的匹配点（`saves/analysis/seed_spread.md`，现在已经有种子 0–2 的版本）。
- **改写问题**：`scripts/exp/para_eval.sh <GPU> <规模>` 对每个方法的 forget05 模型用新的评测配置 `configs/eval/tofu_para.yaml`（只有遗忘集的三个指标）各跑两遍：原问题（`_q`）和 TOFU 的 `paraphrased_question`（`_pq`）。模型清单与 A1 / A2 P0 相同（NEAR 为 v2，3B LUNAR 为正确的匹配点）；`near:` 的模型临时物化，评测完删除。结果 `saves/eval/para/<规模>_f05/<方法>_{q,pq}/`，汇总 `saves/analysis/para_question_table.md`（Prob、ROUGE、truth ratio 的原问题 / 改写问题，以及两者之比）。

### `b2_ablation.sh`：NEAR（v2）组件消融（3B forget05）
| 名字 | 改了什么 | 回答的问题 |
|---|---|---|
| `npqall` | 每步从全部 train 邻居随机抽（不固定每题 3 位） | 固定邻居是否必要（v1 时期：采样时名字过度分散） |
| `mnoff` | 邻居名字 token 进 KL | 名字屏蔽是否必要（是否会背下邻居名字） |
| `fp0` | 去掉概率项 | 邻居标定是否必要 |
| `fpmatch` | 所有题同一个目标 | 逐题目标是否必要（v1 时期：离散度被压没） |
| `fpnb` | 逐题邻居水平，不缩放 | 缩放到陌生水平是否必要（v1 时期：过遗忘） |
| `l13` | 编辑层 13–15 | 层位置 |
| `steer` | 从 steering + 回归的解出发（`KL_INIT=stage1`） | 去掉 steering 是否有代价（v1 时期：没有） |
- 结果：`saves/analysis/dist_fix_3B_forget05.md` 里 "Abl ..." 的行（`dist_fix_check.py` 已能识别这些改了 E8 主干的运行）。全部单种子，与 v2 的三个种子（`wb_sup` 波动 ≤ 0.015、utility ≤ 0.006）比较。
