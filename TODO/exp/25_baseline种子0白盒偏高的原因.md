# 25 baseline 种子 0 的白盒偏高：原因与主表的种子规则（2026-11-14，`22` #7）

## 问题
`paper_notes/3` §1 记录：baseline 原始运行（种子 0）的 `wb_sup` 系统性地高于重跑的种子 1、2（3B GA forget01：0.88 对 0.59 / 0.60）。11-14 重新生成主表后，又发现主表里 forget01 的 GA / NPO 匹配点取的是种子 1 的运行，GA 的有监督白盒中位数因此只有 0.27（NEAR 0.29）。

## 做法（只用 CPU，读已有评测）
1. 比对三个种子的评测配置：都是 `EVAL_PROFILE=fast` + 同一个探针（`next_lane_e/f.sh` 只多了 `seed=<n>` 和 `TAG=_s<n>`）；邻居问题集逐条相同（100 条）。
2. 比对第 0 步（三个运行都是同一个原模型）的逐层 `auc[forget | neighbor]`：
3. 比对第 2 步（第一个评测点，2 个优化步）的逐层值、Prob、utility、各作者的回答。
4. 列出所有有 3 个种子的 baseline 运行（1B / 3B forget01 的 GA、NPO，lr 1e-4），逐步比较。

## 结果【数据】
- **评测没有 bug、配置没有差别**：唯一的差别是训练种子（默认 42 对 1、2）。
- **探针本身的噪声**：第 0 步同一个模型，三次评测的逐层 AUC 相差 0.02–0.08（如第 0 层 0.493 / 0.412 / 0.495），所以 `wb_sup`（逐层减去 retain 参照后取最大）有约 ±0.05–0.1 的评测噪声。
- **模型确实不同**：第 2 步，三个种子的 Prob（3B GA 0.18 / 0.19 / 0.17）和 utility（0.52 / 0.52 / 0.52）几乎一样，但种子 0 在第 3–20 层的 AUC 整体高出 0.1–0.25（如第 10 层 0.94 对 0.75 / 0.68）。
- 15 个可比的（运行, 步）里，种子 0 更高的有 12 个，中位数高 0.16；第 2 步的差距最大（1B GA 0.54 对 0.19 / 0.25；3B GA 0.88 对 0.59 / 0.60；3B NPO 0.87 对 0.59 / 0.62）。
- 1B / 3B、GA / NPO 的种子 0 运行用的是**同一个种子（42）**，因而数据顺序完全相同；第 2 步的 GA 与 NPO 几乎是同一个模型（NPO 在第一步的梯度近似 GA）。

【我的判断】
- "种子 0 系统性偏高"其实是**同一个数据顺序（种子 42）在 4 个运行里重复出现**，不是 4 次独立的证据。forget01 每个 epoch 只有 2 个优化步（40 条，有效 batch 32：第一步 32 条、第二步 8 条），第 2 步的模型取决于这两个 batch 里两位作者各占多少；按作者不均衡的更新会让被遗忘作者的激活在作者层面更好分（`wb_sup` 测的就是这个），而 Prob / utility 看不出来。这一点没有直接验证（需要复原 batch 组成）。
- 3 个种子不够判断种子 42 是"偏高的那个"还是"正常的那个"：1B GA 的三个值 0.19–0.54，跨度本身就和方法之间的差距一样大。**早期检查点的 `wb_sup` 对训练种子很敏感**，这是论文里要说明的。

## 发现的规则问题与处理
- `cells.py` 读 `saves/tofu_unlearn` 时把 `_s1`、`_s2` 的运行也当作候选点，`best_matched` 在 3 个种子里取 utility 最高的（utility 在小数点后两位相同，等于随机挑种子）；而 NEAR 的种子放在 `*_v4_s<n>`，从来不进主表。**baseline 是"三选一"，NEAR 是"固定种子 0"，口径不一致。**
- **已改**：`cells.py` 默认只用每个方法的默认种子（`SEED_RUN_RE` 跳过 `_s<n>` 的运行）；`CELLS_ALL_SEEDS=1` 恢复旧行为（已另存 `saves/analysis/main_table_allseeds.*` 作对照）。主表、附录表、Pareto 图、E7 都已重新生成。

| 9 格中位数 `wb_sup` | 三个种子取最好的（旧） | 只用默认种子（新，主表） | 三个种子的匹配点取平均（参考） |
|---|---|---|---|
| GA | 0.27 | **0.50** | 0.33 |
| NPO | 0.59 | **0.62** | 0.62 |
| NEAR | 0.29 | 0.29 | — |
utility、Prob、mia 的中位数不变（只有 forget01 的 1B / 3B 两格的 GA / NPO 匹配点变了，utility 相同）。
