# 4 今晚（服务器空）跑难跑的：8B 与大遗忘集；明天跑小的

> 依据 `paper_notes/5_*` 的方阵与当前 `saves/`。已完成不再列：forget01 全部三个规模（含 8B RMU / LUNAR 曲线 / 旧 c6 / 新两个层位置）、forget10 参考、forget05×1B 的 NEAR 新旧、forget05×3B 的上游（选层 14）。
> 记号：**[串]** 同一队列里按顺序（用 `&&` 连好，可整行粘贴）；**队列之间互相独立，可在不同 GPU 上同时开**（每个队列一个 shell）。

## 0. 先说一个会影响今晚安排的发现（forget05×1B 的新旧结果已出）
| forget05 × 1B（retain：Prob 0.130 / mia 0.361 / util 0.595） | Prob | mia | extr | util | retain 生成 | wb_unsup |
|---|---|---|---|---|---|---|
| 旧方法 c7 l7-9 | 0.239 | 0.669 | 0.054 | 0.535 | 0.569 | 0.889 |
| 新方法 100 步 | 0.236 | 0.886 | 0.199 | 0.474 | 0.513 | 0.010 |
| 新方法 300 步 | 0.160 | 0.878 | 0.142 | 0.512 | 0.513 | 0.011 |
- 新方法在 forget05 上白盒仍然干净（0.01），Prob 随步数下降（0.236 → 0.160）；但 **mia 0.88（retain 0.36）、utility 0.51（retain 0.595）、retain 生成 0.51（retain 0.81）都明显差于 forget01 上的表现**。forget05 比 forget01 难：铰链只约束真实答案概率，遗忘集变大后对保持集的伤害和 mia 的偏离都变大。
- 所以今晚 forget05 上的新方法统一用 **300 步**；如何改善（retain 权重、层位置、forget05 的 KL 对数）放在明天的 1B 小实验里查，不要在 8B 上试。
- forget05×1B 的 GradAscent（lr 2e-5）只有 3 个评测点，第 3 个点（步 21）已经崩溃（Prob 0.039、utility 0.247），步 14 为 0.209 / 0.452：窗口很窄。今晚 8B 的 forget05 baseline 的 lr 取得更保守（下面）。

### 队列 A：forget05 × 8B 的 NEAR（上游 → 旧 → 新 **[串]**）
```
RUV_KS=1,3,5,10 TASK_NAME=forget05_Llama8B_v2/near_tofu_Llama-3.1-8B-Instruct_forget05_ks bash scripts/NEAR/single_run.sh <GPU> "1" && TASK_NAME=forget05_Llama8B_v2/near_tofu_Llama-3.1-8B-Instruct_forget05_ks COEFFS="7" MODES="all" LAYERS="[15,16,17,18,19,20]" bash scripts/NEAR/sweep_select.sh <GPU> && EXTRA_WDOWN="wdown.gen_batch_size=8" EXTRA_EVAL="eval.tofu.batch_size=4" SELECT_TASK_NAME=forget05_Llama8B_v2/near_tofu_Llama-3.1-8B-Instruct_forget05_ks OUT_PREFIX=forget05_Llama8B_v2 EVAL_PROFILE=full INCLUDE_ANSWER=1 LAYER=17,18,19 COEFF=7 MULTI_LAYER=increment SEQUENTIAL=1 RETAIN_WEIGHTS="1" bash scripts/NEAR/sweep_w_down.sh <GPU> && EXTRA_EVAL="eval.tofu.batch_size=4" KL_STEPS=300 OUT_PREFIX=forget05_Llama8B_v3 UPSTREAM_PREFIX=forget05_Llama8B_v2 EXTRA_WDOWN="wdown.kl.fr_batch_size=4 wdown.kl.batch_size=8 wdown.gen_batch_size=8" FP_WEIGHT=1 FP_TARGET=unseen FP_MODE=match KL_FORGET_W=0 KL_INIT=original KL_WEIGHTS=1 EVAL_PROFILE=full COEFFS="7" LAYER_SETS="16,17,18" bash scripts/NEAR/sweep_kl.sh <GPU>
```
- 旧方法的层 17-18-19 沿用 forget01 的 8B 配方（选层 19）；选层结束后看一眼 `layer_selection.json`，若选的不是 19，Ctrl-C 后把 `LAYER` 改成 `选层-2,选层-1,选层` 再接着跑后两步。新方法的 16-17-18 是 forget01 上 8B 的最好层位置，不依赖选层。
- 如时间够，之后可补新方法的 22-23-24（把最后一条的 `LAYER_SETS` 改掉）；不是必做。

### 队列 B：forget05 × 8B 的 baseline（**[串]**，按重要性排序；NPO 与 RMU 需要参照模型，加降显存参数）
lr 取得比 forget01 的 8B 保守（forget05 的步数是 3.5 倍；未验证，所以每个 epoch 评测，看轨迹）：GA / GD 1e-5，SimNPO / NPO 2e-5，RMU 2e-5。
```

```
（GA、GD、SimNPO 不需要参照模型，先跑；NPO / RMU 放最后，万一时间不够只损失这两条。8B 的 forget05 baseline 是方阵里的选做格子，所以这条队列允许跑不完。）
