# 21 A2：选层规则与名字长度控制（待实现说明，2026-11-13）

> 本文只描述要改什么、为什么改、改成什么样；不含代码。相关规格见 `A2_SPEC.md`（§9 偏离记录），命令见 `19_A2_影子探针攻击_命令.md`。
> 所有改动都只影响 `attack` / `p0` 两个子命令的**分析阶段**：只用 CPU，读已有的激活文件（`saves/spa/**/*.npz`），**不需要重做影子编辑，也不需要重新采集激活**。

---

## 1. 为什么要改

### 1.1 选层：现在的规则在 Act 上选错了层
【数据】3B / 8B 的 NEAR-Act（`saves/analysis/spa_{3B,8B}_act_real/summary.json` 的逐层曲线）：
- 影子内的交叉验证 AUC 从**第一个编辑层开始就全部是 1.00**（3B 从第 13 层起，8B 从第 19 层起）。
- 现在的规则取交叉验证最大值所在的层，并列时取**第一个**，于是选中了紧挨编辑层的那一层。
- 而那几层恰好是“低谷”：provider 的编辑（10 个作者、较大系数）和影子的编辑（2 个作者、较小系数）在这里表现不同，迁移 AUC 只有 0.3–0.6。
- 再往下游（3B 第 18 层以后，8B 第 22 层以后），real 的 Q1 / Q2 都在 0.84–1.00，而 retain 对照在同样的层上大多 ≤ 0.5。

结论：信号存在，但选层规则把它错过了。现在的“迁移失败”不能写成“Act 抵抗了自适应攻击”。

### 1.2 编辑层之前：有方法无关的“残留认识”
【数据】规格版探针（P1）在编辑层**之前**的一段层上，real 明显高于 retain 对照（1B 第 5–6 层 0.81–0.86 对 0.53–0.56；3B 第 9–11 层 0.92–0.98 对 0.73–0.82；8B 第 8–15 层 0.92–1.00 对 0.45–0.62）。
这些层上 M' 的激活与原模型完全相同，所以这个信号对所有只编辑中间层的方法都成立。上面的层段是**看了目标标签后**挑出来的，必须用事先定好的规则正式验证。

### 1.3 名字长度混淆
【数据】P0 的分数与名字 token 数的 Spearman 相关为 −0.6 到 −0.78；retain 模型（从没见过 F）上 P0 的 Q1 也有 0.62–0.84。F 对陌生人这个池子，单靠名字风格就能部分分开。

## 3. 要实现成什么样

### 3.1 四个选层规则（都不用目标标签）
对每个（探针, 探针类型）组合，同时报告下面四种规则的结果：

| 规则名 | 用哪些层 | 说明 |
|---|---|---|
| `cv`（现有） | 交叉验证最大的那一层，并列取第一个 | 保留，作为对照 |
| `cv_deepest` | 交叉验证与最大值相差不超过 0.005 的层里，**最深**的那一层 | 解决“全是 1.00、取了第一个”的问题 |
| `post_edit_mean` | **最后一个编辑层之后**的全部层 | 每层各一个探针（就是第 345 行循环里已经在拟合的那些），各自的作者分数先用**该探针在自己训练数据上的分数的均值和标准差**标准化，再在这些层上取平均，得到一个作者分数 |
| `pre_edit_mean` | **第一个编辑层之前**的全部层 | 做法同上；它测的是“残留认识”，不是编辑痕迹 |

要点：
- 攻击者知道编辑层（它们是算法的超参数），所以按编辑层划分层段不算使用标签。
- 标准化只能用训练数据的分数，不能用目标模型上的分数。
- 没有编辑层的方法（GA、NPO、RMU、MEOW 等，`--edit-layers` 为空）只报告 `cv` 和 `cv_deepest`。
- 每个规则都对 Q1（F 对陌生人）和 Q2（F 对保留作者）调用 `evaluate_transfer`。
- 第 345 行那个逐层循环已经在每层拟合探针了，新规则应当**复用这些探针**，不要再拟合一遍（否则 8B 会很慢）。

### 3.2 名字长度控制（不用标签）
- 对每个规则得到的作者分数，取**全部候选作者**（F、H_B、R_B 放在一起），以名字 token 数为自变量做一次普通最小二乘（截距 + 斜率），用残差代替原分数，再算 Q1 / Q2。
- 回归不能分组、不能用 F / 负例的标签。
- token 数全都相同时（理论上不会发生）直接用原分数。
- 原分数和长度修正后的分数**都要报告**。

### 3.3 输出
- `summary.json`：每个（探针, 类型）下新增一个按规则分组的部分：该规则用到的层、Q1 / Q2 的 `evaluate_transfer` 结果、长度修正后的 Q1 / Q2 结果。现有字段（`selected_layer`、`pools`、`auc_by_layer` 等）保持不变，旧的读取脚本不受影响。
- `summary.md`：在现有表格下面加一张“选层规则”表，每行一个（探针, 类型, 规则），列为：所用层、Q1 AUC [区间]（零线）、Q2 AUC（零线）、长度修正后的 Q1、长度修正后的 Q2。
- `cmd_p0` 的汇总表：同样加一张按规则分的表。

### 3.4 测试（`tests/test_spa.py`）
用现有的合成激活工具（`make_acts`、`_known_world`）各加一个场景：
1. **编辑层之后有指纹，但紧挨编辑层的一层是“低谷”、交叉验证在多层并列为 1.00**：`cv` 选在低谷、迁移失败；`cv_deepest` 和 `post_edit_mean` 能找到指纹，并超过零线。
2. **只有编辑层之前的“认识”信号**：`pre_edit_mean` 的 Q1 高；`post_edit_mean` 的 Q2 接近 0.5。
3. **分数只由名字长度决定**（人为让 F 的名字更短）：原分数的 Q1 高，长度修正后回到接近 0.5。
4. 没有编辑层时只出现 `cv` 和 `cv_deepest`。

## 4. 改完之后怎么重算（只用 CPU）

激活都在你本地的 `saves/spa/` 下，重跑分析即可：
- Act 三个规模、real 和 retain 对照：对每个 `saves/spa/<规模>_act_<real|retain>/`，用 `spa.py attack` 加上原来的 `--shadow`（5 个文件）、`--target`、`--edit-layers`（1B `7 8 9`，3B `12 13 14`，8B `17 18 19`），输出到原来的 `saves/analysis/spa_<规模>_act_<条件>/`。最简单的做法是删掉 `logs/spa/<规模>_act_<条件>/attack.v2.done` 后重跑对应的 `spa_lane_<规模>_act.sh`：编辑和采集都有完成标记，会被跳过，只重跑攻击。
- P0：重跑 `a2_p0_lane.sh`，采集步骤会被跳过，只重跑最后的 `p0`。

## 5. 结果怎么读（事先约定）
- 主结果用 `post_edit_mean`（编辑痕迹）和 `pre_edit_mean`（残留认识），都报告长度修正后的数；`cv` 和 `cv_deepest` 作为敏感性分析。
- 只有当 real 超过零线、**并且**明显高于同规则下的 retain 对照时，才算识别成功。
- 预期（来自逐层曲线，尚未正式验证）：Act 在 3B / 8B 上 `post_edit_mean` 成功、1B 不成功；`pre_edit_mean` 在三个规模上都高于 retain，并且对 NEAR-Dist、LUNAR 同样成立。
