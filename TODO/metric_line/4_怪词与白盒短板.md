# 4 怪词与白盒短板（来自 near_line/11、12 的结果）

## 问题
UD（`ud_bb`、`ud_wb_*`）在新的 NEAR 配置上暴露了两个缺口。

## 结果
1. **流畅度缺口**：B+ans c7 的 forget 回答里 12/40 以 "Basis to …" 开头（"Basil" 被扰动后的近邻词），`ud_bb` 只有 0.046，因为 UD 只查拒答 / 退化 / 重复。answer_coeff 0.5 / 0.3 之后变成 "Beneer / Benever / Benely"，`ud_bb` 仍只有 0.04–0.06。加 KL 之后这些词消失（`ud_bb` 0.0）。首词集中度不适合作为指标：forget 集只有两位作者，回答本来就常以作者名开头（Nikolai / Basil 占大头是正常的）。
2. **白盒短板**：NEAR 的 `ud_wb_unsup` 0.95–0.996（KL 单层 l9 最低 0.953），LUNAR（forget01，c0.5–2）只有 0.41–0.57。因此目前只能说 NEAR 在黑盒上更隐蔽，不能说全面更隐蔽。
3. 对 baseline（GA / NPO / …）还没有跑 UD（`tune.sh` 默认 `PROBE=0`）。

## 下一步
1. 为 UD 加**流畅度通道**：用 full 或 retain 模型给每条回答算平均 token 负对数似然（困惑度），与 retain 回答的分布比较，量化怪词；不用首词集中度。
2. 拓宽白盒检测位置（全 prompt token 均值，而不只是 eoi 位置），再判断 NEAR 的白盒痕迹是否真的高；声称降低 footprint 之前必须做这一步。
3. 对调好 lr 的 baseline 选定配置后用 `PROBE=1` 重跑一次，得到 UD，与 NEAR / LUNAR 画同一张 Pareto 图。
4. 论文汇报：黑盒 `bb` / `entity_bb` + 白盒 `wb_unsup` + `model_utility` + benign 拒答率一起报，并说明白盒上 NEAR 目前不占优。
