# 5 采样层面的可检测度：多次采样下，遗忘问题的回答像不像“没见过的作者”

## 问题
贪心单次回答看不出遗忘把概率质量挪到了哪里。攻击者可以对同一问题采样 N 次。需要知道：(a) 被遗忘模型的回答是否比“没见过作者”时更稳定或更不稳定；(b) 是否反复出现同一个替代名字（跨样本、跨问题）；(c) 真实答案是否仍会在采样中泄漏。参照是**同一个模型对 holdout 问题**的统计（holdout 作者它也没见过，不需要 retain 模型）；retain 模型作为另一行对照。
动机：我们的方法有明确的遗忘目标（K 个邻居的分布 + 铰链落点），GA 没有目标，被挤出来的质量落在哪里是任意的；若 retain 对这类问题本来就不稳定，则“GA 不稳定”不是痕迹，要和参照比，不是“越稳越好”。

## 做法
`scripts/analysis/sample_consistency.py`（每个模型对 forget01 与 holdout01 各问题采样 N 次，温度 1，同一聊天提示）：
- `self_agreement`：N 个回答两两 ROUGE-L F1 的均值（1＝总是同一回答）。
- `distinct_names` / `modal_name_share`：每个问题里不在问题文本中的“替代名字”的种类数 / 最常用名字的占比。
- `cross_question_name_share` / `cross_distinct_names`：同一个替代名字在多少比例的不同问题里出现 / 不同名字数除以问题数（新方法最可能暴露：总用同一个替代名）。
- `leak_key@k`、`leak_rouge@k`：前 k 次采样里至少一次包含真实答案的事实词（大写词、数字）≥ 75% / ROUGE-L recall ≥ 0.7 的问题比例。
- 每项都有 forget / holdout 两列；判读看 forget 与 holdout 的差，以及与 retain 行的差。
测试：`tests/test_sample_consistency.py`（度量的合成用例 + 小随机模型的采样形状；真实模型的结果未在本机验证——本机无 GPU / 模型缓存）。
